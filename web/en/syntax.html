Syntax guide

An MDitor document is Markdown. Any Markdown viewer can read it, and MDitor LaSee lays the same text out as a report and exports it as a PDF. When you edit in the Document tab, this syntax is written for you, so there’s nothing to memorize.

Structure

WriteMeaning
# TitleDocument title. Write it once, on the very first line (optional).
## HeadingSection heading. Divides the document into sections.
### HeadingBlock heading. Forms a single unit (a block) with the one body element right below it.
- ItemList. Each two spaces of indent moves an item one level down (up to three levels).
> NoteNote: a remark in small type attached to the bottom of a block. One per line.
A plain lineParagraph. Each line is one paragraph.

A block is a heading (###) + one body element (a paragraph, list, table or image) + notes (>). In the PDF, when a page break falls inside a block, the whole block moves to the next page. Body content without a heading is a block too. Separate blocks with one blank line.

Headings of level #### and below are read as block headings. There are no numbered lists (1.), code blocks or links. Just type numbers as text.

first line<br>second linefirst line
second line
  • ** and ~~ only pair up when the character right after the opening marker and right before the closing marker aren’t spaces. ** text ** is not formatting.
  • Unpaired markers stay as plain text, so you can type a footnote mark like 1.31** as is.
  • To write a marker as plain text, put \ in front of it: \*\*, \{red}, \<br>.
  • Headings (# ## ###) take formatting too. A heading is one line, so <br> becomes a space. Image captions don’t take formatting.
Korean tag names work too and mean the same thing: {빨강} = {red}, {파랑} = {blue}, {회색} = {gray}, {기울임} = {italic}, {밑줄} = {underline}, {음영} = {shade}. A document sticks to one tag language: the first tag in the document decides it, and in a document with no tags yet, the editor’s language decides.

Tables

  • Rows above the separator (|---|) are the header. The header can span several rows, and it repeats on the next page when a table runs across pages.
  • The separator sets column alignment: :--- left, :---: center, ---: right.
  • Merge cells: a cell containing only < merges with the cell to its left; a cell containing only ^ merges with the cell above. Every row keeps the same number of cells. Header and body cells merge separately, and a merge that wouldn’t form a rectangle doesn’t happen.
  • Cell shading: wrap the whole cell content in {shade}…{/shade}.
  • Inside a cell, write | as \| and a line break as <br>. To put a lone < or ^ in a cell as text, write \< or \^.
  • Every row must have as many cells as the header. Missing cells are filled in as empty; extra cells are reported as an error with the line number.

Images

Write ![caption](image address) on a line of its own. When you add an image with the editor’s Image button, it is uploaded to the service’s image storage and its address is filled in for you, so the image comes along when you download the MD file or send a link. The caption appears below the image.

Each image file can be up to 10 MB, and images whose longer side is over 1600px are scaled down before upload. PNG, JPEG, GIF and WebP are supported.

Pages

  • Page breaks come from actually rendering the PDF. The blue dashed line in the preview (‘Page 2’) is exactly where the PDF turns the page.
  • A block that doesn’t fit in the space left on a page moves to the next page as a whole. A table taller than a page splits between rows and repeats its header.
  • In Document → Page setup you can change the paper size, orientation, margins and font size, and start every section on a new page.
